# JEG-1566 Why panel: roster % from DDFOpportunity (2026-11-07)

Follow-up to #1349 (Why panel) and #1352-era JEG-1558 (app/next/ddf-opportunity.js, on main).

- find.html now loads `ddf-opportunity.js` after `v2/finder.js`; without it the % line was hidden on the live page.
- `DDFWhy` calls `DDFOpportunity.rosterImprovementPct(trade, 'sender'|'partner', ctx)` and uses the module's own `shown`
  (truncated toward zero, one decimal, never -0) and `band`. Header line: `Your roster +0.9%. Theirs -1.2%, slightly worse.`
  followed by the module's partner `sentence` verbatim (sender-facing, never promises acceptance). The Net row of the
  give/get table also carries `Your roster +x%`. Raw units stay in "Show the numbers".
- The only wording ours: the short band name (better, essentially unchanged, slightly worse, clearly worse), mapped from
  the module's `band` id because the module exposes ids and full labels, not short names (brief, Jeremy 2026-11-07).
- Formatting: sign only when non-zero ("0.0%", never "-0.0%"), ASCII minus, one decimal. Hidden when the module is absent
  or either side is unsized (pct null: base under MIN_BASE).
- Tests (tests/test_ddf_why.py): the stub is gone; table-driven trades on the real module for each band, the zero cases
  (partner -0.083 reads 0.0%), the unsized case, absent module; formatting is computed independently in Python. Render test
  at 1440 and 390 checks the % line shape and the 44px Why button (round(h, 1)).
