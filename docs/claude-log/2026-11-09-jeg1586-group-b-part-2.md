# JEG-1586 group B (part 2): live page synthetic and two v2 weight harnesses (2026-11-09)

No product or published-number change. Each assertion changed was stale, not a code defect.

- `test_live_page_synthetic`: `tests/rendered_gate/live.mjs` was rewritten by JEG-1539 to check the twelve redesigned root
  pages, the legacy-route redirects, `/classic/` and the 404 page; the test still expected the old v2 tab list and
  mutated `index.html` v2 sections. The page-name list now matches live.mjs. The two mutation guards moved to the
  surfaces that exist: `find.html` with `<main>` hidden must fail with "<main> not visible", and `values.html` with its
  `#rows` table emptied must fail with the "DDF Value" problem. Both guards still fail the run when the page breaks.
- `test_v2_group_weight_render`: opened `v2/` (the JEG-1539 redirect stub). It now uses the shared `_served` from
  `test_v2_names_render` (build-only shell at `/v2-app.html`, held sources pinned). Its "raw totals" mutation guard still
  fails the run.
- `test_v2_weight_render`: its harness builds the shell into a copy of `dist/` at the root, but the landing tab has been the
  Value chart since JEG-1106 (Jeremy, 2026-10-25), so the Trade targets table it waits for is not rendered until that tab
  is opened. It now opens `#trade-targets`. Its three mutation guards are unchanged and still pass.
- `v2_player_tags_render` and `v2_values_math_tip_render` already pass on main (they share the harness #1386 fixed); no
  change.

## Group D items in the same PR (test environment, no assertion loosened)

- `test_check_weekly_freshness`: the full-suite job runs in GitHub Actions, so `GITHUB_ACTIONS=true` leaked into every
  `main()` call and added `::error::` lines the tests did not expect. The harness now removes it unless a test passes it
  explicitly (two tests do and still assert the annotation). The module fails without the change under
  `GITHUB_ACTIONS=true` and passes with it.
- `tests.test_edge_drift_workflow`: `ModuleNotFoundError: No module named 'yaml'` in the nightly shard. `full-suite.yml` now
  installs `pyyaml==6.0.2` (the pin `main-writer-checks.yml` uses) beside pytest. Workflow change only; not exercised
  until the next nightly run.
